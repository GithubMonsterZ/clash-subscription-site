# VPS38 CDN改造参考

- 父目标：本机可经Cloudflare访问VPS38直出节点。
- 阶段梯：现状取证→新入口与证书→本机验证→订阅和本机同步。
- 当前阶段：替换原直连入口及增加订阅生成器WS能力。
- 当前主要矛盾：旧节点直连20443，未配置CDN兼容的WS、TLS和新端口。
- 退出证据：Windows物理接口独立代理HTTPS成功，出口38.49.54.61；线上原URL内容与通过测试的配置一致，另五份订阅不变。
- 明确延后：长期耐封、吞吐排名、其它电脑自动刷新和其他节点迁移。
- 唯一不确定问题：现有Xray/Mihomo版本能否经Cloudflare的8443完成WS+TLS回源。
- 停止搜索的证据：官方端口和Origin CA契约、双端WS示例明确；剩余版本兼容由现有二进制语法检查和真实Windows链路判断。

## 官方资料
- [official-doc] Xray WS — https://xtls.github.io/config/transports/websocket.html — WS路径必须一致，标准WebSocket；官方更建议XHTTP，当前先选现有客户端兼容的WS，不声称无特征。
- [official-doc] Cloudflare端口 — https://developers.cloudflare.com/fundamentals/reference/network-ports/ — HTTPS8443在普通代理支持列表中；原20443不在其中。
- [official-doc] Origin CA — https://developers.cloudflare.com/ssl/origin-configuration/origin-ca/ — 可提交自有CSR，源证书配合Full(strict)，不得给本机安装源CA或关闭证书检查。

## Demo对照
- [official-demo] Xray WSS服务器/客户端示例 — https://raw.githubusercontent.com/XTLS/Xray-examples/main/VLESS-WSS-Nginx/server.jsonc — VLESS decryption none与network ws、统一path，无Vision flow；采用传输参数，TLS由现有Xray直接终止，不新增Nginx。
- [mature-demo] Mihomo WS配置示例 — https://wiki.metacubex.one/config/proxies/transport/ — network ws与ws-opts.path/headers.Host；同步生成器与Mihomo测试，保留旧REALITY分支。
- [official-demo] Cloudflare WebSocket开通示例 — https://developers.cloudflare.com/network/websockets/ — Network中WebSockets开关，所有套餐支持；握手仍受WAF检查，实际链路验证后才认定可用。

## 写法决定
采用新8443、Cloudflare橙云、WS+TLS、Origin CA+strict；私钥本地生成受保护，systemd LoadCredential传入；服务只允许Cloudflare IPv4回源段访问8443。保留现有UUID、节点名称和订阅token，仅改目标节点；旧20443 TCP入口由原服务改造移除，HY2 UDP同数字端口不变。
